Specific Resource Availability and Utilisation Reporting

What I Did

  • Designed the Power BI semantic model for availability, utilisation and activity reporting
  • Built time and event-based measures for resource activity, episode length and utilisation percentage
  • Created highly filterable report pages for area, resource type and operational grouping
  • Built detail pages for reviewing individual resource activity and exception cases
  • Produced help, information and version pages so users could understand metric definitions and report changes

Context

A specialist operational staff group needed a dedicated report showing availability, activity and utilisation across different regions and responder types. Existing reporting did not capture the group in a way that reflected how they operated, making it difficult for managers to understand service coverage, compare activity and identify under-used or over-stretched resource patterns.

The report was designed for group management, operational leadership and performance teams. It needed to support both a quick headline view and deeper analysis of individual activity periods, with enough filtering to separate areas, resource types and episode characteristics without requiring separate reports.

Key Reporting Challenges

  • Capturing availability data for a group whose activity was not represented well in standard reporting feeds
  • Combining resource availability, operational events and episode timing into a single reporting structure
  • Calculating utilisation consistently across different resource types and working patterns
  • Providing detailed drill-through while keeping the main report usable for operational managers
  • Making filter state visible so users could understand exactly which activity was included in each view

Data Model

The data model brought together raw availability records, resource attributes, region and type lookups, and activity event timings. New data capture was required because the group reported in a non-standard way, so the model had to align availability periods with operational events before utilisation could be calculated reliably.

Temporal modelling was used to capture event times and calculate availability durations, activity durations and utilisation rates. The semantic model supported headline measures, trend analysis and drill-through to individual activity periods without duplicating metric logic across pages.

Report Design

The report presented headline availability, activity and utilisation metrics alongside time-based charts, event-based views and detailed tables. Field parameters allowed users to change analytical perspective without moving between separate pages, and an applied-filter display made the current reporting context visible.

Additional pages supported detailed review of individual records, user guidance, report definitions and version information. This gave operational users a practical daily report while preserving the audit trail needed for performance conversations and data quality investigation.

Outcome

The report gave managers a clearer view of how specialist resources were available and used across operational areas. It supported performance review, workforce planning and service coverage discussions using a consistent set of metrics rather than ad hoc extracts.

By combining availability capture, event timing and Power BI modelling, the solution created a reusable reporting structure for a resource group that had previously been difficult to monitor through standard operational reports.
