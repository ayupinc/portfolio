Questionnaire Workflow Reporting and Governance

What I Did

  • Designed the Power BI semantic model supporting workflow questionnaire reporting
  • Built Power Query processes to transform questionnaire responses into reportable workflow structures
  • Developed DAX measures for workflow activity, pathway utilisation, response analysis and outcome reporting
  • Created branch-specific reporting structures from a common questionnaire framework
  • Designed reporting administration processes allowing questionnaire changes to be managed without report redevelopment
  • Built governance reporting for question mappings, response cleaning and configuration validation
  • Produced user guidance, metric definitions and maintenance documentation

Context

I developed this reporting solution to support analysis of a structured workflow questionnaire framework used within a case management system. Individual workflow sessions could contain dozens of questions, multiple branching pathways and repeated executions within the same case.

Questions, responses and workflow paths evolved over time as operational processes changed. Question text itself effectively formed part of the reporting schema, meaning that changes to wording, spelling or structure could create new reporting fields and fragment historical analysis.

Although I had already developed the underlying analytical model, covered separately within the Analytics Engineering section, the reporting challenge was different. My objective was to create a Power BI solution capable of analysing workflow behaviour while remaining resilient to ongoing questionnaire changes.

Key Reporting Challenges

  • Reporting seven workflow branches from a single questionnaire framework
  • Converting response-level data into workflow-level reporting
  • Managing changing questions and responses without report redevelopment
  • Creating common analytical dimensions across otherwise independent workflows
  • Supporting both episode-level and response-level analysis from the same semantic model

Data Model

I designed the semantic model around questionnaire episodes and cleaned responses.

A key challenge was that seven workflow branches originated from a single questionnaire framework. Although users experienced these as separate operational processes, they shared a common questionnaire framework while requiring different reporting structures to support meaningful analysis.

Power Query was used to construct branch-specific reporting tables while maintaining a common analytical model for cross-workflow reporting. Question and response variants were normalised to preserve continuity of reporting despite operational changes to questionnaire content.

Multi-response questions required separate handling to support accurate counting and trend analysis. I introduced helper tables where responses needed to be analysed individually while still retaining their relationship to the originating workflow episode.

I also developed a separate analytical layer that consolidated information from a specific operational process across multiple workflow branches into a single reporting structure, enabling comparison across workflows that originally captured this information in different ways.

The resulting semantic model supported both high-level workflow reporting and detailed drill-through to individual workflow episodes without requiring multiple reporting models.

Reporting Administration and Governance

One of the more significant reporting challenges was that questionnaire questions and responses were not version controlled. Changes to wording, spelling, numbering and structure created effectively new reporting fields while still representing the same operational concept.

To maintain reporting consistency, I developed a reporting administration layer alongside the dashboard. This included:

  • Controlled mappings for question and response variants
  • Governance reporting for configuration validation
  • Business-maintained cleaning and translation tables
  • Reporting processes for identifying new or changed questionnaire content
  • Validation of branch-specific reporting outputs

This approach allowed operational changes to be incorporated into reporting without requiring redevelopment of the Power BI solution.

Report Design

I designed the report around workflow analysis rather than individual questionnaire responses. Pages focused on:

  • Workflow pathway selection
  • Branch utilisation
  • Response category analysis
  • Completion and duration trends
  • Outcome analysis
  • Individual workflow review

Interactive filtering, drill-through and contextual navigation enabled users to move between organisation-level activity and individual workflow episodes. Additional pages supported workflow performance analysis through duration, cycle-time and utilisation reporting.

My design objective was to make complex branching processes understandable, without exposing users to the underlying question-response structure. Users were able to identify common workflow routes, compare pathway utilisation and investigate variations in operational behaviour through a consistent reporting experience.

Outcome

The completed solution transformed a complex questionnaire system into a sustainable reporting platform.

Operational managers were able to monitor workflow utilisation, identify changes in pathway usage, analyse outcomes and review operational behaviour across large volumes of questionnaire activity.

By introducing governance processes and reporting administration capabilities, I was able to support ongoing questionnaire changes without requiring repeated report redevelopment. This reduced maintenance effort while preserving continuity of reporting over time.

The semantic model allowed multiple workflow branches, reporting views and governance processes to operate from a single reporting framework without duplication of business logic.
